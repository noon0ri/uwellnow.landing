# 유웰나우 3D 스크롤 랜딩 — 설계

작성일 2026-11-18

## 의도와 이유

uwellnow.com 홈(`/`)을 실제로 리뉴얼한다. **성공 기준은 사전예약 전환**이다. 3D 연출은 제품 이해와 "우리 공간에 놓인 모습"의 실감을 주는 수단이고, 사전예약으로 가는 길을 막아서는 안 된다(로딩, 모바일 성능, 상시 CTA).

대상: 도입을 결정하는 사업자(피트니스, 스파·사우나, 아파트 커뮤니티, 오피스, 라운지 운영자).

## 목표 / 비목표 / 안티골

**목표**
- 스크롤에 따라 디스펜서 3D 모델이 회전·줌인/줌아웃하며 기능을 강조한다.
- 5개 공간 사진에 기기가 놓인 장면으로 이어진다.
- 마지막에 기기 디스플레이에서 기능 1개 + 맛 1개를 고르면 컵에 음료가 채워지고, 사전예약 CTA로 이어진다.
- 사용자 앱 / 관리자 앱 섹션을 짧게 유지한다.

**비목표**
- 영어 버전(문구는 한 파일에 모아 두어 나중에 추가 가능하게만).
- 사전예약 폼 자체(기존 `/pre-registration` 페이지로 링크).
- 원료소개, 고객지원 등 다른 페이지.
- 실제 키오스크 UI 재현.

**안티골** (동작해도 실패인 것)
- 3D 로딩 때문에 첫 화면/CTA가 늦게 뜬다.
- 모바일에서 버벅이거나 스크롤이 막힌다.
- 공간 장면에서 기기가 두 대로 보인다.
- 사전예약 버튼을 찾으려면 3D를 끝까지 봐야 한다.

## 제약

- **3D 모델** `디스펜서 3D 모델.glb` (2.7MB): AI 생성(스캔형) 모델. 메시 1개, 머티리얼 1개, 2048² JPEG 텍스처 1장, 애니메이션 없음. 디스플레이·노즐·컵이 별도 부품이 아니다(텍스처에 그려져 있음). 바운딩 박스 약 0.82 × 1.90 × 0.59 — 실제 스펙 비율(W75.5 × H177 × D56.2cm)과 일치. UV가 잘게 조각나 근접 줌 시 거칠어질 수 있다.
- **공간 사진**에는 이미 기기가 정면 각도로 합성되어 있다. → 3D를 사진 위에 겹쳐 두면 안 된다(바통 터치 방식으로 해결).
- **현재 사이트**: Vite + React + Tailwind, S3 + CloudFront 정적 배포, GA4 `G-CRPVFTV8N0`, 폰트 Freesentation(가변 woff2), 모노톤 컬러(`#171717`, `#fff`, `#f2f2f2`, `#eaeaea`, `#393939`, `#222`).
- 한국어만.

## 접근 방식 (검토한 것)

| 방식 | 장점 | 단점 |
|---|---|---|
| **1. React Three Fiber + drei + GSAP ScrollTrigger** ✅ 선택 | 디스플레이 UI를 drei `<Html>`로 3D 화면 위치에 그대로 붙여 React 상태·GA 이벤트를 일반 코드로 처리. 연출 수정이 코드 수정뿐. | 의존성 증가(약 +150KB gzip) |
| 2. 순수 three.js + GSAP | 의존성 최소 | 디스플레이 UI ↔ 3D 동기화, 리사이즈, 정리 코드를 직접 작성. React와 두 세계를 손으로 연결 |
| 3. 사전 렌더 이미지 시퀀스 + 마지막만 실시간 3D | 조명 품질 최고, 텍스처 결함 은폐 | 프레임 수백 장으로 모바일 로딩 무거움, 별도 렌더 파이프라인, 연출 수정마다 재렌더. 전환 목표와 충돌 |

사용자가 1번을 선택했다. 이유: 마지막 체험이 인터랙티브 UI라 React와 3D의 결합이 핵심이다.

## 사용자가 결정한 것

- 새 프로젝트로 이 폴더에 만들고, 나중에 홈(`/`)만 교체한다.
- 공간 장면은 **A-1 바통 터치**: 3D 기기가 사진 속 기기와 같은 화면 위치·크기·정면 각도에 맞춰 선 순간 3D가 사라지고 사진이 이어받는다. 다음 공간으로 넘어갈 때 3D가 다시 나타나 다음 사진의 기기 위치로 이동한다.
- 공간 사진은 현재 사이트에서 가져온다.
- 체험은 **기능 1개 + 맛 1개**를 고르면 음료가 나온다.
- 앱 섹션은 짧게 유지하고, 원료와 맛은 체험에 흡수한다.
- 한국어만 먼저.
- 구현은 1번(R3F + GSAP).

## 기술 결정 (Claude의 판단)

- Vite + React + TypeScript + Tailwind, `@react-three/fiber`, `@react-three/drei`, `gsap` (ScrollTrigger). 부드러운 스크롤 라이브러리(Lenis)는 필요할 때만 추가.
- 3D 캔버스 하나를 화면에 고정(sticky)하고, 섹션별 스크롤 진행도로 카메라·기기 변환을 GSAP 타임라인으로 구동.
- **바통 터치**: 사진마다 기기의 화면 내 박스(정규화 좌표 x, y, 높이)를 측정해 상수로 둔다. 사진은 `object-fit: cover`로 깔리므로, 뷰포트 비율에 따른 크롭을 계산해 3D 기기의 투영 위치를 맞춘다. 맞춘 순간 3D 불투명도 0, 사진 1로 크로스페이드.
- **디스플레이 UI**: drei `<Html transform>`을 모델 디스플레이 위치에 붙인다(위치는 모델을 보고 측정). 체험 단계에서는 카메라가 화면에 꽉 차게 다가간다.
- **컵·음료**: 컵은 반투명 원기둥(또는 lathe), 물줄기는 가는 원기둥 스케일 애니메이션, 액체는 컵 안 원기둥의 높이 애니메이션. 노즐 위치는 모델을 보고 측정.
- **성능**: 첫 화면 텍스트와 CTA는 HTML로 즉시 렌더하고, 3D는 지연 로드하며 로딩 중에는 `hero-poster` 이미지를 보여준다. DPR 상한은 2(모바일 1.5). `prefers-reduced-motion`이면 회전·줌 대신 정적 전환.
- **모바일**: 같은 흐름. 카메라 구도만 세로에 맞춘다. 사진은 기기 중심으로 크롭.
- **GA4**: 기존 태그 유지. 이벤트 `cta_click`(위치 파라미터), `experience_complete`(function, flavor).
- **CTA 링크**: `/pre-registration` (같은 도메인 배포를 전제. 로컬 확인 시에는 절대 URL로 바꿔도 됨).
- **배포 산출물**: `vite build` 정적 결과물. 업로드는 사용자 몫.
- **기존 사이트와의 공존** (Claude의 판단): 기존 앱이 같은 버킷의 `/assets/`를 쓰므로 새 빌드는 `build.assetsDir = 'assets-home'`으로 분리해 파일 충돌을 막는다. 새 홈의 모든 링크는 일반 `<a href>`(전체 페이지 이동)로 둔다. 주의: 기존 앱의 내부 라우터가 "/" 링크를 클라이언트에서 처리하면 옛 홈이 렌더될 수 있다 — 교체 시 기존 앱의 홈 링크를 전체 페이지 이동으로 바꾸는 작업이 기존 코드베이스 쪽에 필요하다(이 프로젝트 범위 밖, 사용자에게 고지).
- **컵 중복 방지** (Claude의 판단): 3D 컵에 음료가 채워지는 연출은 필수(사용자 요청). 모델 텍스처에 컵이 그려져 있으면 텍스처에서 해당 영역을 주변 색으로 지운 뒤 3D 컵을 그 자리에 둔다. 컵 모양은 공간 사진 속 컵과 비슷한 텀블러형, 액체가 보이도록 반투명.
